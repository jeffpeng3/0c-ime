# 輸入與候選

這一頁說明單一 Mixed profile、注音／羅馬字／英文混打、逐片段候選與長詞合併。日文轉換品質仍在評測，這裡只寫程式已實作的行為與已知限制。

## 單一 Mixed profile

Windows 只有一個 TSF profile，名稱是「Mixed」。注音、日文羅馬字與英文在同一個輸入法與同一個組字區裡輸入，不需要先切換語言或模式。日文路徑需要有日文資料才會啟用；沒有資料時注音與英文照常。

- 「主要語言」是排序偏好，影響先驗、語言切換成本、輸出變體與 `auto`／`primary` 模式先常駐的模型。主要語言不會擋住其他語言。
- 設定程式的 Mixed 頁可以選 `zh` 或 `ja`。
- 舊版的 ja-JP「靈犀日本語」profile 已移除；升級時會從語言清單清掉。
- Windows 的 Mixed profile 固定開啟混打，沒有「關閉混打」的開關。Linux 與 macOS 仍依設定檔的中英混打開關，行為不與 Windows 的單一 profile 完全相同。

## 同一個組字區怎麼判斷語言

引擎逐鍵判斷，不使用語言模式切換。規則是：

| 按鍵內容 | 路徑 |
|---|---|
| 合法注音序列 | 留在注音，注音 golden 不變 |
| 有載入日文資料時的合法羅馬字，且不是英文詞或英文詞前綴 | 組成かな，交給日文轉換 |
| 大寫、全角英數、數字、網址、email、識別字、已學過的詞 | 照字面保留 |
| 小寫且是英文詞典裡的完整單字 | 預設照字面保留，可提供英文補全與拼字修正；`ja-ambiguous=kana` 或按 Shift+Tab 時改成かな（P2-52） |
| 打不成合法羅馬字的英數 | 照字面保留，避免整串變成かな |

英文字可以用 `core/english` 的詞典自動補完。日文與英文混打時，日文段與照字面段會分開轉換，英文與網址不會被送進かな轉換。

因此同一個組字區可以出現「注音中文 + 日文かな + 英文」的片段。這是逐鍵推斷的結果，不是整句翻譯；短字同時是英文與羅馬字時仍有歧義，例如 `code`、`sake`。預設照舊由詞典、大小寫與已學過的詞決定，另外提供「日英同形時優先」與 Shift+Tab 兩種明確出口，見下一節。

## 注音

標準注音輸入：

- 注音符號加聲調，一聲是空白。
- 打完注音按 Enter 送出，或按 ↓／空白開候選。
- 注音打到一半時空白仍是一聲；候選開著時空白換頁。
- 打錯注音時提示預設開啟。按了聲調但讀音沒有字時，引擎擋下聲調並提示；緊接著再按同一個聲調會照舊留下注音。

注音的 45 個 golden 案例在本機通過。這是協定層級的行為 baseline，不證明所有詞庫與所有應用程式的選字品質。

## 候選

### 開啟與操作

候選窗顯示與候選選取模式是兩個狀態。打完注音、按空白或外殼要求開候選後，清單只是**顯示**；按 ↓ 才進入明確的**選取模式**，反白停在目前那一項，不必再按一次 ↓。

| 動作 | 按鍵 |
|---|---|
| 開候選 | ↓；「空白鍵選字」開啟且沒有未完成符號時也可用空白 |
| 移動組字游標，候選跟著新片段重算 | 顯示中：←→、Home／End |
| 進入候選選取模式 | ↓（從目前反白開始） |
| 移動反白 | 選取模式中：↑↓ |
| 換頁 | 選取模式中：←→、空白、PageUp／PageDown |
| 第一個／最後一個候選 | 選取模式中：Home／End |
| 直接選第 1 到第 10 項 | 1–0，或設定的字母選字鍵 |
| 選字 | Enter、數字鍵或滑鼠 |
| 離開選取模式、繼續組字 | 打字、Esc、選字或提交 |
| 關閉候選、保留組字 | Esc、Backspace 或 Delete |
| 切換詞長 | Tab／Shift+Tab，或在候選清單走到其他詞長 |

顯示中的 ←／→ 與 Home／End 不會翻頁或移動候選反白。游標換到另一個片段時，候選清單重算成該片段的內容，頁碼回到第一頁、反白回到第一項，不沿用上一個片段的頁碼或反白。Home／End 在顯示中移到整個組字區的頭尾；進入選取模式後才改成第一個／最後一個候選。打字會離開選取模式並照常繼續組字，候選窗再跟著新的完整音節出現。

各平台外殼的按鍵細節可能不同，滑鼠與候選窗位置也由外殼決定。

### 逐片段候選跟著游標

組字區由多個片段組成，例如「我」「風景」「abc」。候選清單只針對游標所在的片段，快照的 `start`／`length` 會跟著游標移動。

- 游標在「我」時，候選範圍是第一個片段。
- 游標移到「風景」時，候選範圍換成「風景」，長詞仍是一項候選。
- 游標在片段結尾時屬於下一個片段；在整段結尾時停在最後一個片段。

候選窗顯示中按 Home／End／←／→ 時，核心自己移動游標並回傳新片段的候選，外殼不必先關窗再重開。Windows TSF 外殼另外保留一層保險：候選窗**沒有開著**時，游標移動後會再要求一次新片段的候選；其他外殼目前沒有同樣的保險。按 ↓ 仍以目前游標所在的片段開候選並進入選取模式。

這項行為在 `core/session` 與 Rust `candidate_model` 有測試，Windows WPF 實機檢查在 `p2-mixed` harness 裡；VM 驗收是 **NOT RUN**，所以不能說已經在 Windows 實機看過。

### 長詞合併

詞庫裡的長詞可以跨過多個輸入片段。當引擎選中整詞時：

- 組字區把它顯示成一個片段，不會拆成多個片段的自動拼接。
- 候選清單只出現一項長詞候選，例如 `麻婆豆腐` 只出現一次。
- 詞庫沒有整詞或分數不支持時，仍可能拆成較短的詞。長詞合併不保證每個長詞都會被選中。

`core/session` 的長詞測試與 `core/lattice` 的跨片段查詢測試涵蓋這個行為；`testdata/mixed` 的 `noisy:long-match` 也用它觀察合併後的評分單位。這些是程式與 benchmark 證據，Windows 實機的長詞單一候選檢查同樣列在 NOT RUN 的 VM suite。

## 日文輸入

日文核心支援羅馬字與直接かな組字、文節轉換、候選、Tab／Shift+Tab 換文節、F6 到 F10 變換字種，以及記号與顔文字辭典。Mixed profile 會把合法羅馬字自動轉到日文路徑。

### 日英同形：英文詞與羅馬字撞在一起（P2-52）

`kanji`、`sake`、`sushi`、`kana`、`anime`、`ramen` 這類字同時在英文詞典裡，又是合法的羅馬字。舊版一律照英文，使用者沒有辦法把它們打成かな。現在有三層規則，預設完全不變：

1. **預設英文優先**（`ja-ambiguous=english`）：小寫的詞典英文詞照字面，與舊版相同。
2. **明確改成かな**：待定按鍵還沒送出時按 **Shift+Tab**。整段按鍵會原樣交給日文路徑，已打的前綴保留；像 `kan` 按 Shift+Tab 會先顯示 `かn`，再打 `ji` 就是 `かんじ`。打不成合法羅馬字（`kubectl`、`hello`）、大寫（`Kanji`）、網址與識別字不受影響，按了也只保留原樣。
3. **改變預設**：設定「日英同形時優先」選 `kana`（`0c-update set ja-ambiguous kana`）。此後只要按鍵是合法羅馬字就優先かな；大寫、網址、email、數字、識別字，以及「我的詞彙」裡的英文詞仍是英文。

具體例子：

| 按鍵 | 預設（english） | Shift+Tab | 設定 kana |
|---|---|---|---|
| `kanji` | `kanji` | `かんじ` | `かんじ` |
| `sake` | `sake` | `さけ` | `さけ` |
| `sushi` | `sushi` | `すし` | `すし` |
| `kan` + `ji` | `kanji` 英文 | `かんじ` | `かんじ` |
| `hello` | `hello` | `hello`（不合法羅馬字） | `hello` |
| `kubectl` | `kubectl` | `kubectl`（識別字） | `kubectl` |
| `Kanji` | `Kanji` | `Kanji`（大寫） | `Kanji` |

Shift+Tab 不占用既有按鍵：候選窗開著時仍照原本的候選操作；一般英數、數字與標點走混打；單按 Shift 才是中英切換，Shift+Tab 是組合鍵不算；Ctrl＋標點只用 `, . ' ; ? ! : ( )`；切換簡體字是 Ctrl+Shift+F11。Windows 的 TSF 本來就把 Shift+Tab 送成 `BackTab`，其他外殼也一樣，所以不需要新增系統快捷鍵或攔截 Ctrl 組合鍵。

候選清單同時列出英文與かな（按 ↓ 選）是另一種做法，這次沒有採用。它要把英文與日文的候選、排序與學習放進同一個清單，還要決定選かな後如何切換 runtime、怎麼保留已打前綴與既有的逐片段候選；比 Shift+Tab 多出跨語言候選模型與更多不確定性。現階段先做明確、可預測的出口；等跨語言候選真的有需求與評測資料再做。

#### 碰撞盤點

以 `core/ja/input` 的預設羅馬字表重播每個詞（全部小寫字母、中途每一步都能插入、結尾沒有未完成前綴，單獨的 `n` 以「ん」結束）：

- `data/english/esdb.tsv`：82,000 個詞，4,937 個（6.0%）也是完整合法的羅馬字序列。
- `data/english/technical.tsv`：104 個產品詞，18 個（17.3%）也是完整合法的羅馬字序列。
- 兩份合併、同詞取較高頻率後，最高頻的碰撞是 `have`（はゔぇ，299）、`receive`（れせいゔぇ，294）、`chinese`（ちねせ，290）、`code`（こで，288）、`file`（ふぃぇ，287）、`name`（なめ，286）、`time`（ちめ，285）、`data`（だた，264）、`language`（ぁんぐあげ，262）、`message`（めっさげ，255）、`make`（まけ，246）、`release`（れぇあせ，244）、`go`（ご，242）、`api`（あぴ，241）、`openai`（おぺない，233）、`boolean`（ぼおぇあん，227）、`database`（だたばせ，225）、`foo`（ふぉお，202）。
- 日常日文借詞的實際碰撞：`kanji`→かんじ（60）、`kana`→かな（60）、`sushi`→すし（60）、`ramen`→らめん（60）、`anime`→あにめ（50）、`emoji`→えもじ（50）、`karaoke`→からおけ（50）、`ninja`→にんじゃ（50）、`tempura` 在詞典裡但按鍵不是完整合法序列，`tsunami`→つなみ（50）、`tofu`→とふ（40）、`sake`→さけ（35）。`sudoku` 不在這兩份詞典。
- esdb 的頻率集中在 40／50／60（產品詞表另外到 200–300），所以「最高頻」多半反映 technical.tsv 的排序初值，不是一般英文語料。

### 目前可用的部分

- 羅馬字組字：`core/ja/input` 的內建羅馬字表。
- 日文轉換：`core/ja/decode` 的統計詞典與 Viterbi。
- 文節：`core/ja/decode/segment.go`，候選標題顯示「文節 N/M」。
- 記号與顔文字載入器：`core/ja/rewrite` 可以讀取 `data/ja/symbols/*.tsv`。
- 個人學習介面：`core/ja/personal` 與 decoder 的 `Learning` 鉤子存在。

### 目前未接上的部分

以下是文件與設定畫面看得到、但引擎還沒有實際套用的項目。寫在這裡是為了避免把設定畫面當成已生效功能：

- 日文輸入方式 `ja-input-method`：設定可保存 `romaji`／`kana`，引擎目前沒有讀取這個值來切換 composer。
- ライブ変換 `ja-live-conversion`：`core/ja/live` 有控制器與測試，產品 session 還沒有接上。
- 記号開關 `ja-symbols`、日文學習 `ja-learning`、日文神經模型 `ja-model`：設定可保存，引擎目前沒有對應的 health／open 能力旗標來套用。`core/ja/rewrite` 的記号載入器與 `core/ja/personal` 的學習鉤子還沒有接到 `newJaLanguage` 的正式路徑。
- 日文模型包：設定畫面沒有模型包選項；日文 reranker／punct 由 `models/pairing.lock.json` 的單一模型包載入；模型不可用時保留統計轉換。
- Windows 套件以 `--ja-data` 放入編譯後的 `data/ja/`，並附上引擎實際載入的 `data/ja/lexicon/words.tsv`、`data/ja/connection.tsv`；這兩個 TSV 由 `0c-japack` 從同一次編譯的 `lexicon.bin` 匯出。

原始碼的 `data/ja` 目錄有 `lexicon/words.tsv` 與 `connection.tsv`，開發時可以直接讓引擎載入。`make assets LANG=ja` 的 `build/ja` 也有相同的執行期布局。

## 英文與混打

- Mixed profile 直接打英文，不需要先按 Shift 或切模式。`hello` 會直接送出 `hello`。
- 英文補全與拼字修正由設定控制；按 Tab 接受、Esc 關閉。
- 「中英文之間自動加空格」預設關閉。開啟後，送出的文字在中文與英文字母直接相連處補一個半形空格，例如「用Python寫」送出「用 Python 寫」。已有空格、標點與數字旁不補。
- 私人欄位與密碼欄位不學習、不送模型；外殼依平台規則處理。

## 品質與未驗證事項

- 注音有 45 個 golden 案例與 Phase 2 前的量測；免選字是目標，不是保證。
- 混合語言 benchmark 的數字是 baseline 與改進依據，不是上線門檻；它不載入模型。
- 日文目前是 137 詞條的種子資料，轉換分數受詞典覆蓋限制，不能拿來和 Mozc 或注音的 86.0% 比較。
- 日文模型仍是未訓練 placeholder，沒有品質數字。
- Windows Phase 2 VM 驗收 NOT RUN；單一 Mixed profile、逐片段候選與長詞候選的實機結果尚待補。
