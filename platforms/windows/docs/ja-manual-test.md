# Windows TSF 日文手動驗收（T26）

這份清單驗收 T26 的 Windows TSF 外殼：日文按鍵轉發、文節樣式、輸入方式顯示、候選窗與文節對應、能力旗標。
CI 只跑 `cargo check`／Rust 單元測試與 T05 的 Windows 建置；下面每一項都需要互動桌面與實際宿主。

## 前置

1. 使用 T28 的安裝程式加入 ja-JP profile，或暫時以測試腳本註冊日文 profile。
2. 啟動使用暫存個人詞庫的測試引擎（不要用日常 `user.json`）。
3. 確認 `%LOCALAPPDATA%\Zuin\tsf.log` 可寫，需要按鍵細節時才建立 `tsf-debug`。
4. 引擎回報 `japanese=true`、`convert_keys=true`、`clause_display=true`；可用 `0c-update status -json -diagnostics` 或測試腳本核對。
5. 每一步記錄宿主、Windows 版本、輸入方式、預期與實際結果。

## 1. 基本輸入與送出

在記事本、WPF 測試程式、Windows Terminal 各做一次：

- [ ] 切到日文 profile，輸入 `nihongo`，組字區顯示 `にほんご`。
- [ ] 按 Space，出現変換候選（例如「日本語」）。
- [ ] 再按 Space 或 ↓ 換候選，按 Enter 確定並送出。
- [ ] 変換中按 Escape 回到かな，再按 Escape 清掉整段組字。
- [ ] 変換中按 Tab 移到下一個文節，Shift+Tab 回到上一個文節。
- [ ] 沒有変換時按 Enter 直接送出整段かな。
- [ ] 連續輸入、快速輸入、空白與標點不會掉字。
- [ ] 送出後立刻繼續輸入，前文不會重複或消失。

## 2. 實體変換鍵

使用日文鍵盤（或把按鍵送出成下列 VK）：

- [ ] `VK_CONVERT`（変換）開始変換／前進候選。
- [ ] `VK_NONCONVERT`（無変換）回到かな或取消目前轉換。
- [ ] F6 轉ひらがな。
- [ ] F7 轉カタカナ。
- [ ] F8 轉半角カナ。
- [ ] F9 轉全角英数。
- [ ] F10 轉半角英数。
- [ ] 変換鍵與 F6–F10 在組字中不會先送出組字；按下後組字仍在，結果照核心快照更新。
- [ ] 沒有日文能力的舊引擎：上述按鍵照舊交給應用程式，不會被吃掉。

## 3. 文節樣式與目前文節

- [ ] 変換後每個文節都有底線（一般文節細實線）。
- [ ] 目前文節是粗實線，Tab／Shift+Tab 移動時粗線跟著換。
- [ ] 只畫底線的宿主（WPF、Chromium）也看得出粗細差異。
- [ ] 支援原生顯示的宿主（Word）沒有出現兩套互相衝突的底線。
- [ ] `clause_display=false` 的引擎：文節樣式退回一般組字底線，不畫粗線。
- [ ] 文節邊界改變（候選換文節）時畫面不閃爍、不殘留上一組底線。

## 4. 輸入指示器與輸入方式

- [ ] 日文模式的工作列指示器顯示「あ」（羅馬字輸入），不是「中」。
- [ ] かな直接輸入時顯示「カ」。
- [ ] 滑鼠停在指示器上，說明是「靈犀日本語（ローマ字入力）」或「靈犀日本語（かな入力）」。
- [ ] 切回注音後指示器回到「中」／「简」，英文模式回到「英」。
- [ ] 舊引擎沒有 `japanese` 能力時不顯示日文指示。

## 5. 候選窗與文節對應

- [ ] 変換後候選窗列出目前文節的候選。
- [ ] 候選窗標題顯示「文節 2/3」這類位置，和組字區的粗線文節一致。
- [ ] Tab／Shift+Tab 換文節後，候選內容與標題都跟著換。
- [ ] 上下鍵、數字鍵、滑鼠點選都能選字。
- [ ] 翻頁後頁碼正確，選字後組字區只替換目前文節。
- [ ] 沒有候選時不顯示空的候選窗。
- [ ] 候選窗在游標附近，Chromium／WebView2 宿主版面晚到時仍會移到正確位置。

## 6. TSF 焦點切換

- [ ] 組字中按 Alt+Tab 到別的程式再回來，組字已送出到原欄位，不會留在新程式。
- [ ] 組字中點另一個輸入框：原欄位收到送出文字，新欄位從乾淨狀態開始。
- [ ] Excel 儲存格還沒進入編輯時直接打日文，焦點交給儲存格編輯器後組字跟著搬過去（同注音的 #189）。
- [ ] 在 WPF、記事本、Terminal、Edge 之間來回切換，輸入指示器跟著各程式記住的模式。
- [ ] 變換中切換焦點，不會把候選窗留在前景或別的程式上。
- [ ] 停用再啟用輸入法（Win+Space）後可繼續輸入。

## 7. 密碼與私人欄位

- [ ] 密碼欄位（InputScope Password）不送任何按鍵到引擎：按日文字母與変換鍵都沒有組字、沒有候選、`tsf.log` 不記鍵碼。
- [ ] PIN 欄位同上。
- [ ] 密碼欄位不建立新 session、不學習、不送前文。
- [ ] 從一般欄位切到密碼欄位時，未送出的組字不會流入密碼欄位。
- [ ] 只標 `IS_PRIVATE` 的欄位（Chrome 無痕、Firefox 私密視窗）照常組字與送出，但請求帶 `private`：不學習、不讀前文。
- [ ] 私人欄位裡的変換與候選選字正常，選過的字不會進個人詞庫。

## 8. 能力旗標與舊引擎

- [ ] 舊引擎（沒有 `japanese`）：日文按鍵全部照舊交給應用程式，注音行為不變。
- [ ] 有 `japanese` 但沒有 `convert_keys`：羅馬字與かな可輸入，変換／F6–F10 交給應用程式。
- [ ] 有 `japanese` 但沒有 `clause_display`：可輸入與変換，不畫文節樣式、不顯示文節標題。
- [ ] 引擎在輸入中重啟（改設定）：下一個按鍵重開 session，日文組字不遺失。
- [ ] 引擎重啟成舊版後，外殼停止送日文按鍵、指示器回到注音。

## 9. 沙箱、32 位元與其他宿主

- [ ] Windows 11 搜尋框（SearchHost）可輸入日文、変換、以數字鍵選字。
- [ ] WebView2 宿主（Teams／Outlook 新版）候選窗看得到，滑鼠選字有效。
- [ ] 32 位元 WPF 程式載入 `x86\0c_tsf.dll` 後日文輸入正常。
- [ ] 記事本、Word、Windows Terminal、Edge 各至少完成一次「輸入→変換→選字→送出」。
- [ ] UI-less 宿主（遊戲內聊天）不會另外跳出不該出現的候選窗。

## 回報格式

每項失敗請附：

1. 宿主程式與版本、Windows 版本、32／64 位元。
2. 輸入方式（romaji／kana）與能力旗標（`japanese`、`convert_keys`、`clause_display`）。
3. 實際按鍵順序（只記按鍵名稱，不記輸入內容）。
4. `tsf.log` 尾端相關行；需要按鍵細節時才附 `tsf-debug` 的紀錄，用完刪除。
5. 截圖：組字區、候選窗、工作列指示器。
